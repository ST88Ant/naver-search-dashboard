# 네이버 마켓 인사이트 — EDA 대시보드

[NAVER API HUB](https://api.ncloud-docs.com/docs/naver-api-hub-overview) 공식 문서를 기반으로
검색어에 대한 **뉴스 · 블로그 · 웹문서 · 이미지 · 지식iN · 지역 · 카페글 · 백과사전** 검색 결과와
**검색어 트렌드**(데이터랩 통합검색 상대 검색량)를 수집해 Streamlit 대시보드로 EDA 를 수행합니다.

## 화면 구성 — 질문 순서

페이지를 데이터 소스가 아니라 **질문 순서**로 배열했습니다. 앞에서 뒤로 읽으면 하나의 이야기가 됩니다.

| 페이지 | 답하는 질문 | 쓰는 데이터 |
|---|---|---|
| 📈 검색 관심도 | 얼마나 찾나 | 트렌드 API |
| 👥 성별·연령 분석 | 누가 찾나 | 트렌드 API (세그먼트별 15회 호출) |
| 💬 채널별 언급량 | 얼마나 이야기되나 | 검색 API |
| 🌐 출처 분석 | 어디서 이야기되나 | 검색 API (도메인) |
| 🔑 연관 키워드 | 뭐라고 이야기하나 | 검색 API (형태소) |
| 💡 키워드 기회 | 그래서 쓸 만한가 | 두 API 를 함께 |
| 🗂️ 원자료 | 직접 확인하고 싶다 | 전체 + 내려받기 |

각 페이지는 **결론 하나 → 헤드라인 그래프 하나 → 근거 여러 개** 순서로 쌓여 있습니다.

### 두 API 는 서로 다른 것을 잽니다

- **검색 API** 는 *공급* 을 잽니다. 그 검색어로 글이 얼마나 쌓였는지입니다. 검색량이 아닙니다.
- **트렌드 API** 는 *수요* 를 잽니다. 얼마나 찾는지이고, 절대 수치가 아닌 상대 점수입니다.

`💡 키워드 기회` 페이지가 이 둘을 나눠 "찾는 사람 대비 글이 적은" 검색어를 가려냅니다.

## 주요 기능

- 검색어를 **쉼표(,)로 구분**해 여러 개 동시 조회, **기간(시작일·종료일)** 입력
- **자동 요약**: 페이지 상단에 그 질문의 답을 한 문장으로
- 한국어 형태소 분석(`kiwipiepy`)으로 명사·2-gram·동시출현 추출 (미설치 시 정규식 폴백)
- **검색어 간 키워드 교집합·차집합**, **지식iN 실제 질문 목록**
- 원자료 페이지에서 **채널별 CSV 내려받기** (엑셀로 열어도 한글이 깨지지 않는 utf-8-sig)
- 수집 원자료는 `data/<서비스>/<검색어>_<날짜>.csv` 로 자동 저장

## 색 (핑크 테마)

- **계열 색**은 검색어를 구분하는 8색입니다. 1번만 핑크이고 나머지는 다른 색상입니다.
  전부 핑크로 칠하면 선그래프에서 어느 선이 어느 검색어인지 읽을 수 없기 때문입니다.
- **핑크는 히트맵 같은 순차 스케일과 브랜드 색으로** 씁니다.
  베이비핑크 `#f9d4e2` 에서 진분홍 `#65093c` 까지 한 색상으로 이어집니다.
- 계열 팔레트는 색각 이상 분리 기준을 통과했습니다. 인접 쌍 10.3, 전체 쌍 정상시력 18.5
  (OKLab dE x100 / 기준 8, 15). 앞 5색은 산점도처럼 아무 두 점이나 붙는 그래프에서도 안전합니다.
- 값은 `src/naver_insight/eda/charts.py` 와 `.streamlit/config.toml` 두 곳에 있습니다.

## 성능

- 화면 전환은 `st.tabs` 가 아니라 **`st.navigation`** 을 씁니다.
  `st.tabs` 는 화면만 나눌 뿐 **모든 탭의 코드가 매번 실행**되어, 위젯 하나를 누를 때마다
  안 보이는 탭의 표와 그래프까지 다시 그려집니다(접힌 expander 안까지).
  `st.navigation` 은 **선택된 페이지 하나만** 실행합니다.
- 수집·형태소 분석 결과와 모든 집계는 `st.cache_data` 로 캐시
- 조건(검색어·기간·건수)을 바꾼 뒤에만 **🚀 수집 실행** 을 다시 누르면 됨
- 수집 건수 슬라이더가 클수록 첫 수집이 느려짐(기본 200건, 지역은 API 제약으로 최대 5건)

## 사전 준비

1. [NAVER API HUB](https://www.ncloud.com/product/applicationService/naverApiHub) 에서
   애플리케이션을 등록하고 **API Key ID** 와 **API Key** 를 발급받습니다.
   (검색 API, 검색어 트렌드(Search Trend) API 이용 신청)
2. 환경 변수 파일 생성:

   ```bash
   cp .env.example .env
   ```

   `.env` 를 열어 값을 채웁니다.

   ```dotenv
   NAVER_API_KEY_ID=발급받은_API_Key_ID
   NAVER_API_KEY=발급받은_API_Key
   ```

   > `.env` 는 `.gitignore` 에 등록되어 커밋되지 않습니다.
   > 키가 없으면 대시보드 사이드바에서 직접 입력할 수도 있습니다.

## 실행 ([uv](https://docs.astral.sh/uv/))

```bash
uv run streamlit run streamlit_app.py
```

`uv` 가 가상환경(`.venv`)과 의존성, 필요 시 Python 인터프리터까지 자동으로 준비합니다.
브라우저에서 <http://localhost:8501> 이 열립니다.

## 참고

- 검색 API 일 호출 한도: 25,000 회. 지역(local) 검색은 검색어당 최대 5건.
- 검색 API 에는 날짜 파라미터가 없어, 날짜 필드가 있는 **뉴스·블로그**만 수집 후 기간 필터를 적용합니다.
- `검색어 트렌드`의 `ratio` 는 상대값(기간 내 최대치 = 100)이며 절대 검색량이 아닙니다.
- 성별·연령은 **호출마다 정규화가 새로** 되므로, 세그먼트끼리는 검색량의 많고 적음을
  비교할 수 없습니다. 한 세그먼트 안에서 검색어들이 나눠 갖는 **구성비**만 비교합니다.
- 엔드포인트/파라미터: [`docs/api_reference.md`](docs/api_reference.md)
